# Системы знаний для ИИ

> Связи: [[13-video-deep-dives]] [[02-agents-architecture]] [[04-context-engineering]] [[09-math-foundations]] [[11-frontier-unrealized]]

## Обзор темы

Одна из самых важных тем канала в 2026 году.
Как структурировать знания так, чтобы ИИ мог эффективно с ними работать?
Три подхода: RAG, Knowledge Graphs, LLM Knowledge Bases (Карпати).

---

## Подход 1: RAG (Retrieval-Augmented Generation)

**Принцип**: храни документы в векторной БД → при запросе ищи похожие → добавляй в контекст.

**Видео**:
- youtu.be/2AidxIkhc9U — "!!! RAG: Дополненная генерация для ИИ будущего"
- youtu.be/qEwkAH3lwzA — "EmbedAnything: быстрые эмбеддинги для RAG"

**Проблемы RAG**:
| Проблема | Описание |
|---|---|
| Чёрный ящик | Нельзя проследить откуда взята информация |
| Связи теряются | Векторный поиск не понимает логических связей |
| Инфраструктура | Нужна векторная БД, embedding-сервис |
| Деградация | Качество падает на больших корпусах |

---

## Подход 2: Knowledge Graphs (Графы знаний)

**Принцип**: явные узлы (концепты) + явные рёбра (отношения) → ИИ ходит по графу.

**Видео**:
- youtu.be/7PxaphIIefg — "Как графы знаний помогают AI решать алгебру" ★★★★★

**Применение в математике (AutoMathKG)**:

```
Узлы:
  Определение: "Группа — множество с операцией, удовлетворяющей..."
  Теорема: "Теорема Лагранжа: порядок подгруппы делит порядок группы"
  Задача: "Найти все подгруппы Z_6"

Рёбра:
  "Задача использует → Теорему Лагранжа"
  "Теорема следует из → Определения группы"
  "Является частным случаем → Теоремы об орбитах"
```

**Достижения (апрель 2026)**:
- GPT-5.2 + KG → 99% на AIME (олимпиадная математика)
- Lean/Mathlib4: 250 000+ формально доказанных теорем
- o3-mini: 84.4/100 на аспирантских экзаменах

**Ограничения**:
- Требует ручной разметки или автоматического построения
- Дорого создавать для новых доменов
- Нет стандарта для нематематических областей

---

## Подход 3: LLM Knowledge Bases (Карпати, апрель 2026)

**Принцип**: wiki из Markdown-файлов, которую ИИ сам пишет и поддерживает.

**Видео**:
- youtu.be/nHMqJWBWYZI — "Создание саморазвивающихся систем знаний с Claude Code и архитектурой Карпати" ★★★★★
- youtu.be/MGhi216zyqE — "Claude Code: создаём систему знаний AI" ★★★★

### Архитектура

```
Уровень 1: raw/
  ├── статьи.md
  ├── paper.pdf → .md
  ├── repo/ → summary.md
  └── web clips (Obsidian Web Clipper)
  [ИИ только читает, никогда не редактирует]

Уровень 2: wiki/
  ├── concept-A.md
  ├── concept-B.md
  ├── person-Karpathy.md
  └── ...
  [ИИ пишет, обновляет, связывает]

Уровень 3: CLAUDE.md / AGENTS.md
  └── правила, схема, соглашения
  [Человек пишет, ИИ читает]
```

### Цикл обновления

```
1. Пользователь → кидает материал в raw/
2. ИИ → читает raw/ → пишет/обновляет wiki/
3. ИИ → создаёт перекрёстные ссылки
4. Health Check → ИИ сканирует wiki/ → находит:
   - Противоречия → исправляет
   - Пробелы → отмечает как TODO
   - Новые связи → добавляет ссылки
```

### Сравнение с RAG

| | RAG | LLM Knowledge Base |
|---|---|---|
| Хранение | Векторная БД | Markdown-файлы |
| Прозрачность | ❌ Чёрный ящик | ✅ Каждый факт в файле |
| Редактируемость | ❌ Сложно | ✅ Любой текстовый редактор |
| Связи | Неявные | Явные (wiki-ссылки) |
| Инфраструктура | Требуется | Только файловая система |
| Масштаб | Миллионы документов | До ~500K слов оптимально |
| Самообновление | ❌ | ✅ Health check |

### Результаты у Карпати
- Одна тема → 100 статей
- ~400 000 слов
- 0 слов написано вручную
- Инструмент: Claude Code + Obsidian

## Сравнительная таблица трёх подходов

| Критерий | RAG | Knowledge Graph | LLM Wiki |
|---|---|---|---|
| Сложность создания | Средняя | Высокая | Низкая |
| Масштабируемость | ★★★★★ | ★★★ | ★★★ |
| Прозрачность | ★★ | ★★★★★ | ★★★★★ |
| Самообновление | ❌ | ❌ | ✅ |
| Математика/логика | ★★ | ★★★★★ | ★★★ |
| Нарративные знания | ★★★★ | ★★ | ★★★★★ |
| Стоимость запроса | Низкая | Средняя | Низкая |

**Вывод**: нет универсального победителя. Комбинация: LLM Wiki + Knowledge Graph для критичных доменов.

## Что ещё не реализовано ⚠️

### Hybrid Knowledge Architecture
Объединение трёх подходов:
```
raw/ → LLM Wiki (нарративы) + Knowledge Graph (факты) → RAG (поиск)
```
Описано в теории, нет промышленных реализаций.

### Автоматическое построение Knowledge Graph из wiki
LLM Wiki → автоматическое извлечение узлов и рёбер → Knowledge Graph.
Прототипы есть, масштабной системы нет.

### Domain-Specific Memory для агентов
Связано: [[02-agents-architecture]] раздел "Стена памяти".
Агент с персистентной базой знаний по конкретному домену.
Технически реализуемо, стандарта нет.
