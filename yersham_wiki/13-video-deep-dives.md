## Видео 1: Создание саморазвивающихся систем знаний с Claude Code и архитектурой Карпати

**ID**: nHMqJWBWYZI | **Дата**: 9 апреля 2026 | **Просмотры**: 1 300

### Суть
Разбор идеи Андрея Карпати (опубликована 3 апреля 2026) — LLM Knowledge Bases.
Замена RAG для средних объёмов данных: не векторные БД, а живая wiki из Markdown-файлов.

### Архитектура (три слоя)

```
raw/                    ← исходники (статьи, PDF, репозитории)
  └── ИИ читает,           Obsidian Web Clipper → .md
      НЕ редактирует

wiki/                   ← структурированная энциклопедия
  └── ИИ пишет и           ~100 статей, ~400 000 слов
      обновляет            перекрёстные ссылки между концептами

CLAUDE.md               ← правила для агента
  └── что делать,          схема каталогов, соглашения
      как называть         
```

### Цикл работы (три стадии)

1. **Ingestion**: пользователь кидает материалы в `raw/`
2. **Compilation**: LLM читает → пишет wiki-статьи → строит связи
3. **Health check (linting)**: LLM сканирует wiki → находит противоречия → добавляет связи

### Почему это важно

| Традиционный RAG | LLM Knowledge Base (Карпати) |
|---|---|
| Векторная БД (чёрный ящик) | Markdown-файлы (читаемы человеком) |
| Каждый запрос = поиск | Компиляция один раз |
| Связи неявные | Связи явные (ссылки в тексте) |
| Сложно проверить | Аудируемо — каждый факт в файле |
| Требует инфраструктуры | Просто файловая система |

### Инструмент
Claude Code как агент + Obsidian для визуализации.
Конфигурация в `CLAUDE.md` (или `AGENTS.md`).

### Результат у Карпати
Одна тема → ~100 статей → ~400 000 слов.
Карпати не написал ни одного слова напрямую — только кидал исходники.

### Связанные видео на канале
- youtu.be/MGhi216zyqE — "Claude Code: создаём систему знаний AI" (практика)
- youtu.be/7PxaphIIefg — "Как графы знаний помогают AI решать алгебру" (смежная тема)

### Статус идеи
Опубликована апрель 2026. Взорвала AI-сообщество.
Первые реализации появляются. Промышленного стандарта нет.

## Видео 2: Как графы знаний помогают AI решать алгебру

**ID**: 7PxaphIIefg | **Дата**: 9 апреля 2026 | **Просмотры**: 293

### Суть
Почему LLM плохо решают математику и как графы знаний это исправляют.
Основано на исследованиях Princeton + проекте AutoMathKG.

### Проблема LLM в математике

```
LLM работает со статистикой токенов
        ↓
Алгебра требует строгих логических цепочек
        ↓
Модель "угадывает" вместо "доказывает"
        ↓
Ошибки даже в простых задачах
```

### Решение: Knowledge Graph для математики

**Узлы** = математические объекты:
- Определения (что такое группа, кольцо, поле)
- Теоремы (с условиями и заключениями)
- Задачи (с решениями и методами)

**Рёбра** = логические связи:
- "следует из" / "применяется к"
- "частный случай" / "обобщение"
- "используется в доказательстве"

**LLM + граф** = модель "ходит" по графу → не угадывает, а выводит.

### AutoMathKG (реальный проект)

Источники: ProofWiki + учебники + arXiv + TheoremQA
Усилен LLM-аугментацией связей.
Математика = направленный граф из Определений, Теорем, Задач.

### Результаты (апрель 2026)

| Модель | Бенчмарк | Результат |
|--------|----------|-----------|
| GPT-5.2 | AIME 2025 (олимпиада) | **99%** |
| o3-mini | PhD Qualifying Exams | **84.4** баллов |
| Lean/Mathlib4 | Формальные доказательства | 250 000+ теорем |

### Связь с предыдущим видео (Карпати)

```
Карпати: wiki из Markdown с перекрёстными ссылками
                    ↓
Граф знаний: то же самое, но формализованное
                    ↓
Оба подхода: структурированные знания > сырой текст
```

### Статус идеи
Активные исследования (Princeton, Google DeepMind).
До промышленного применения в образовании — 2–3 года.
Lean + Mathlib4 уже используется для верификации математики.

## Видео 3: Claude Code: 12 архитектурных примитивов для production-агентов

**ID v1**: X3cAGKsrCtE | **ID v2**: 1wyvrF77M0o | **Дата**: 6 апреля 2026

### Суть
Разбор утечки исходников Claude Code — 12 инфраструктурных паттернов.
Философия: сначала инфраструктура, потом интеллект (не наоборот).

### 12 примитивов (реконструкция)

**Группа 1: Память и контекст**
1. **CLAUDE.md** — персистентная память проекта (загружается каждую сессию)
2. **Иерархическая память** — компактный индекс (≤200 строк) + файлы по теме + архив транскриптов
3. **Session persistence** — состояние между запусками

**Группа 2: Оркестрация**
4. **Explore → Plan → Act** — явная фаза планирования перед действием
5. **Task tool** — спавн суб-агентов для параллельных задач
6. **Structured aggregation** — родительский агент собирает результаты суб-агентов

**Группа 3: Инструменты и разрешения**
7. **Tool registry** — реестр доступных инструментов
8. **Permission tiers** — уровни доступа (read / write / execute / network)
9. **Sandboxing** — изоляция опасных операций

**Группа 4: Надёжность**
10. **Error recovery patterns** — стратегии восстановления после ошибок
11. **Context compression** — сжатие контекста без потери ключевой информации
12. **Structured output** — типизированный вывод вместо свободного текста

### Ключевая идея
> "Большинство разработчиков агентов начинают с модели и работают наружу.
> Claude Code предлагает противоположное: сначала инфраструктура, потом интеллект."

### Практическое применение
Паттерн Explore → Plan → Act из пункта #4:
```
1. EXPLORE: прочитай все файлы, не меняй ничего
2. PLAN: опиши что будешь делать (текст)
3. ACT: только теперь вноси изменения
```
Добавление явной фазы планирования улучшает качество значительно.

## Видео 5: Устранение отказов AI — Gemma 4 E2B

**ID**: hhXn9OBJJUQ | **Дата**: 9 апреля 2026

### Gemma 4 семейство (вышло 2 апреля 2026)

| Модель | Параметры | Особенность |
|--------|-----------|-------------|
| E2B | ~2B эффективных | Edge-устройства, $35 Raspberry Pi |
| E4B | ~4B эффективных | Смартфоны |
| 26B MoE | Mixture of Experts | Баланс скорость/качество |
| 31B Dense | 31 млрд | Бьёт 400B конкурентов |

### Возможности E2B (уникальные для 2B модели)

- **128K** контекстное окно
- **140+ языков** нативно
- Нативное видео + аудио + изображения
- Встроенный **reasoning mode** (думает перед ответом)

### Почему важно
Мощный ИИ на устройстве без облака = приватность + оффлайн + дешевизна.
Демократизация: не нужен дата-центр.

## Видео 6: Заря рекурсивного самоулучшения

**ID**: JCI_Ipa1AG8

### Суть концепции

```
ИИ_v1 улучшает → ИИ_v2
ИИ_v2 улучшает → ИИ_v3 (умнее ИИ_v1 в квадрате)
...
ИИ_vN → потенциально неограниченный рост
```

### Три барьера (из видео)

1. **Верификация**: как ИИ знает, что новая версия лучше?
2. **Безопасность**: как остановить процесс если что-то пошло не так?
3. **Цели**: сохраняются ли исходные цели через поколения?

### Текущий статус
- Теоретически описано (Юдковский, 2000-е)
- Практических безопасных реализаций нет
- DeepMind, Anthropic изучают в закрытых лабораториях
- Горизонт: 2028+ для первых реальных демонстраций
